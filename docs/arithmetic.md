# Arithmetic specification

This file fixes the arithmetic the hardware computes. The Python models implement it bit for bit:
`python/pqc_golden/modmul.py`, `ntt.py`, `poly.py` and `schedule.py`. The RTL is
`rtl/mod_mul.v`, `rtl/butterfly.v` and `rtl/ntt_core.v`.

| | ML-KEM (Kyber, FIPS 203) | ML-DSA (Dilithium, FIPS 204) |
|---|---|---|
| q | 3329 = 13·2⁸ + 1 (12 bits) | 8380417 = 2²³ − 2¹³ + 1 (23 bits) |
| ζ (root of unity) | 17 (a 256-th root: ζ¹²⁸ = −1) | 1753 (a 512-th root: ζ²⁵⁶ = −1) |
| NTT layers L | 7 (stops one level early) | 8 (complete) |
| n⁻¹ = 2⁻ᴸ mod q | 3303 | 8347681 |
| Twiddle table | 128 entries, 127 used | 256 entries, 255 used |

All values are canonical, `0 ≤ x < q`, at every module boundary. The datapath is 23 bits wide.
ML-KEM values use the low 12 bits.

## 1. Twiddle tables

`zetas[k] = ζ^bitrev_L(k) mod q`, for k = 0 … 2ᴸ − 1. These are plain integers with no Montgomery
factor. They equal the FIPS 203 Appendix A and FIPS 204 Appendix B tables;
`tests/test_params.py` checks the first entries. Entry 0 is never read.

ML-KEM's pointwise multiply also needs `gamma[i] = ζ^(2·bitrev_7(i) + 1) mod q` for i = 0 … 127
(FIPS 203 Appendix A, second table; checked in `tests/test_poly.py`).

The single ROM `rtl/twiddle_rom.v` is generated by `python/gen_vectors.py`:

| ROM address | Content |
|---|---|
| 0 … 127 | ML-KEM `zetas[k]` |
| 128 … 255 | ML-KEM `gamma[i]` |
| 256 … 511 | ML-DSA `zetas[k]` |

## 2. Forward NTT (Cooley–Tukey, FIPS 203 Alg. 9 / FIPS 204 Alg. 41)

The forward NTT runs layer `l = 1 … L`. In layer l:
- butterfly partners are `len = 256 >> l = 2^k` apart, with `k = 8 − l`;
- each block of `2·len` coefficients uses one twiddle, `zetas[2^(l−1) + b]`, where `b = j >> (k+1)` is the block number.

For each `j` with bit k equal to 0:

```
u = f[j], v = f[j + len], z = zetas[2^(l-1) + b]
f[j]       = u + z·v   (mod q)
f[j + len] = u − z·v   (mod q)
```

The output stays in **bit-reversed order**, exactly as FIPS 203/204 define the NTT domain. The
hardware never reorders it.

## 3. Inverse NTT (Gentleman–Sande), using the same table read backwards

The inverse NTT runs level `l = L … 1`, with the same `len`, `k` and block number `b` as the forward
layer l. The twiddle is `zetas[2^l − 1 − b]`, so walking the levels and blocks in order reads the
table from the end towards the start:

```
u = f[j], v = f[j + len], z = zetas[2^l − 1 − b]
f[j]       = u + v          (mod q)
f[j + len] = z·(v − u)      (mod q)      <- subtraction order v − u, not u − v
```

After level 1, every coefficient is multiplied by `n⁻¹` (3303 or 8347681). That is a separate SCALE
pass in the hardware.

**Why the reversed read is correct.** The forward butterfly at (l, b) used `z_f = zetas[2^(l−1)+b]`.
Undoing it needs `(u − v)·z_f⁻¹`. The entry read backwards satisfies
`zetas[2^l − 1 − b] = −z_f⁻¹ (mod q)` for every level and block of both schemes
(`test_backwards_twiddle_is_minus_inverse_of_forward_partner`). So
`z·(v − u) = −z_f⁻¹·(v − u) = (u − v)·z_f⁻¹`.

The negated twiddle and the swapped subtraction cancel only together. Doing just one of them gives
wrong results. FIPS 203 Alg. 10 has the same form. FIPS 204 Alg. 42 writes it as
`−zetas[k]·(t − w)`, which is the same value. The identity is not assumed: the inverse NTT is checked
against the independent by-definition reference
(`test_intt_matches_definition_independently`, whose input comes from the slow definition rather
than the fast forward NTT).

## 4. Pointwise multiply and the full product

**ML-DSA.** The NTT is complete, so `ĉ[i] = â[i]·b̂[i] mod q`, one product per coefficient.

**ML-KEM.** The NTT holds 128 degree-1 pieces. Pair i is `(f̂[2i], f̂[2i+1])`, i = 0 … 127, and stands
for `f̂[2i] + f̂[2i+1]·X mod (X² − γᵢ)` (FIPS 203 Algorithms 11–12):

```
ĉ[2i]   = a0·b0 + a1·b1·γᵢ
ĉ[2i+1] = a0·b1 + a1·b0          with a0 = â[2i], a1 = â[2i+1], b0 = b̂[2i], b1 = b̂[2i+1]
```

The hardware evaluates this in five passes, each a multiply-accumulate `out = u + z·v` per pair:

| Pass | Computes | u | v | z |
|---|---|---|---|---|
| K1 | C[2i] = a1·b1 | 0 | A[2i+1] | B[2i+1] |
| K2 | C[2i] = C[2i]·γᵢ | 0 | C[2i] | gamma ROM |
| K3 | C[2i] = C[2i] + a0·b0 | C[2i] | A[2i] | B[2i] |
| K4 | C[2i+1] = a1·b0 | 0 | A[2i+1] | B[2i] |
| K5 | C[2i+1] = C[2i+1] + a0·b1 | C[2i+1] | A[2i] | B[2i+1] |

**Full product.** `C = A·B mod (X²⁵⁶ + 1, q) = INTT(NTT(A) ∘ NTT(B))`.
`tests/test_poly.py` and `tests/test_schedule.py` check it against schoolbook negacyclic
multiplication (`reference.schoolbook_mul`) for both schemes. They cover zero, one, X, X²⁵⁵, all q−1,
alternating, ramp, sparse and seeded random inputs.

## 5. Multiplier contract

For every build and both schemes:

```
modmul(a, b) = a·b mod q,   for 0 ≤ a, b < q,   with 0 ≤ result < q
```

The two builds differ only in the reduction they use:

| Build | ML-KEM | ML-DSA |
|---|---|---|
| `DIL_SPECIAL = 0` | Barrett (shared ML-DSA-width datapath) | Barrett |
| `DIL_SPECIAL = 1` | Barrett (narrow ML-KEM-only datapath) | special-form reduction (exact) |

Kyber's special form (K-RED) would return 13·a·b instead of a·b. It is out of scope; see the
"Future work" section of `docs/report.md`.

## 6. Widths, bounds and correction steps

All registers are unsigned unless noted. "≤" bounds use `c ≤ (q − 1)²`.

### 6.1 Product (both builds)

| Signal | Width | Bound |
|---|---|---|
| a, b | 23 | < q |
| c = a·b | 46 | ≤ (q−1)² < 2⁴⁶ (ML-KEM: < 2²⁴) |

### 6.2 Barrett (HAC 14.42, base 2)

k is the bit length of q (12 or 23), and `μ = ⌊2^(2k)/q⌋`: 5039 (13 bits) or 8396807 (24 bits).

| Step | ML-DSA | ML-KEM | Register width |
|---|---|---|---|
| q1 = c >> (k−1) | c >> 22, < 2²⁴ | c >> 11, < 2¹³ | 24 |
| q2 = q1·μ | < 2⁴⁸ | < 2²⁶ | 48 |
| q3 = q2 >> (k+1) | q2 >> 24 | q2 >> 13 | 24 |
| r = c − q3·q | [0, 3q) | [0, 3q) | 25 (computed mod 2²⁵) |
| out | r − 2q if r ≥ 2q, else r − q if r ≥ q, else r | same | 23 |

**Error bound, derived here for base 2** (the algorithm is HAC 14.42; the bound is shown directly
rather than cited):
1. Let `Q = ⌊c/q⌋`. Since k is the bit length of q, `2^(k−1) ≤ q < 2^k` (2048 ≤ 3329 < 4096 and
   2²² ≤ 8380417 < 2²³).
2. Write `x = c/2^(k−1)` and `y = 2^(2k)/q`, so `q1 = ⌊x⌋`, `μ = ⌊y⌋` and `c/q = x·y / 2^(k+1)`.
3. **Lower side.** `q1·μ ≤ x·y`, so `q3 = ⌊q1·μ/2^(k+1)⌋ ≤ ⌊c/q⌋ = Q`. Hence `r = c − q3·q ≥ 0`.
4. **Upper side.**
   - `c < q² < 2^(2k)` gives `q1 ≤ 2^(k+1) − 1`.
   - `q ≥ 2^(k−1)` gives `μ ≤ 2^(k+1)`.
   - Then `x·y < (q1 + 1)(μ + 1) = q1·μ + q1 + μ + 1 ≤ q1·μ + 2^(k+2)`.
   - So `c/q < q1·μ/2^(k+1) + 2 < (q3 + 1) + 2`, which means `Q ≤ q3 + 2`.
5. Therefore `r = c − q3·q = (Q − q3)·q + (c mod q) < 3q`.

Since 3q < 2²⁵ for both moduli (3q < 2¹⁴ for ML-KEM), the subtraction can be done on the low 25
bits, and at most two corrections are needed. `q3·q` is built
from shifts and adds:
- `q3·(2²³ − 2¹³ + 1)`;
- `q3·(2¹¹ + 2¹⁰ + 2⁸ + 1)`.

The narrow ML-KEM path in the special-form build uses the same steps with 13-bit `q1`/`q3`, a
26-bit `q2` and a 14-bit `r` (3q = 9987 < 2¹⁴).

Checks: the Python model asserts every width and the `r < 3q` bound on each call, and the 25-bit
truncation is checked against the exact difference. Tests:
- all 3329² ML-KEM pairs (`-m slow`), in Python and in RTL simulation;
- ML-DSA reduction inputs at multiples of q ± 1, powers of two ± 1, the maximum, plus 20,000 random values;
- products of every pair of edge operands (0, 1, 2, 3, q/2, q−2, q−1 and powers of two ± 1) plus 100,000 random pairs.

### 6.3 ML-DSA special-form reduction (exact, no scale factor)

Since `2²³ ≡ 2¹³ − 1 (mod q)`, splitting `x = hi·2²³ + lo` gives `x ≡ lo + hi·(2¹³ − 1)`. Every fold is
non-negative, because `hi·(2¹³ − 1) ≥ 0`:

| Fold | Input bound | hi bound | Output bound | Register width |
|---|---|---|---|---|
| r1 = fold(c) | < 2⁴⁶ | < 2²³ | < 2²³ + 2³⁶ | 37 |
| r2 = fold(r1) | < 2³⁷ | < 2¹⁴ | < 2²³ + 2²⁷ | 28 |
| r3 = fold(r2) | < 2²⁸ | < 2⁵ | < 2²³ + 2¹⁸ = 8650752 < 2q | 24 |
| out | r3 − q if r3 ≥ q, else r3 | | < q | 23 |

So one correction is always enough. The tests are the same as for Barrett, plus the per-fold width
assertions.

### 6.4 Modular add and subtract (inside the butterfly)

- `a + b` is computed in 24 bits; subtract q if the result is ≥ q.
- `a − b` is computed in 24-bit two's complement; add q if bit 23 (the sign) is set.

### 6.5 Constants

n⁻¹ is applied as the z operand of the SCALE pass: 3303 (ML-KEM) or 8347681 (ML-DSA).

## 7. Latency, initiation interval, handshake, reset

| Unit | Latency | Initiation interval | Handshake | Reset |
|---|---|---|---|---|
| `mod_mul` | 4 cycles | 1 | `in_valid` → `out_valid`, no backpressure | clears the valid pipeline only; results already in flight are dropped |
| `butterfly` | 6 cycles (pre-add 1, multiplier 4, post-add 1) | 1 | same | same |
| NTT core, issue to write | D = 8 (RAM read 1, routing register 1, butterfly 6) | 1 group per cycle | `start` when `!busy`, then `done` pulse | aborts the operation |

The no-backpressure choice is deliberate: the core controller never stalls the pipeline. The
schedule is fixed in advance and proven safe by `schedule.py`. The testbenches check back-to-back
operations, random bubbles and a reset with operations in flight (`tb_mod_mul`, `tb_butterfly`).

Butterfly op codes:
- 0 = CT, forward;
- 1 = GS, inverse;
- 2 = MAC, used by pointwise multiply and SCALE: `o0 = u + z·v`, computed like CT's `o0`.
